# Agent 前端信息架构规划

## 1. 背景与目标

当前 Agent 页面同时承载对话、面试上下文、Loop 轨迹、长期记忆、动作草稿、训练任务、用量和活动记录。功能已经具备，但所有内容集中在一个页面，用户很难判断“现在要对话”还是“要管理 Agent 运行结果”。

本次优化的目标是把 Agent 从一个超长页面调整为一个轻量工作台，保留现有数据和操作能力，并让常用入口具备稳定、可复制的 URL。

目标：

- 保留 `/agent` 作为默认的对话工作台，兼容已有的 `sessionId` 和 `agentSessionId` 查询参数。
- 增加记忆、动作与训练、用量与活动三个管理入口，避免所有管理卡片堆在对话页。
- 复用现有 API、状态恢复、动作确认和失败重试逻辑，第一阶段不改 Agent 后端协议。
- 让页面切换可通过浏览器前进/后退和复制链接恢复，不影响普通面试、RAG、简历和原有 Agent 对话入口。

非目标：

- 本阶段不重做 Agent Loop、记忆策略或动作工具协议。
- 不在正式环境 `18083` 上部署。
- 不删除已有功能；管理页只是调整承载位置。

## 2. 页面与职责

| 路径 | 页面名称 | 主要职责 |
| --- | --- | --- |
| `/agent` | 对话工作台 | 选择面试报告和 Agent 会话，选择目标，查看上下文，运行 Loop，与教练对话 |
| `/agent/memory` | 记忆管理 | 查看、编辑、删除长期记忆，查看记忆来源、适用方向和过期时间 |
| `/agent/actions` | 动作与训练 | 管理待确认动作草稿，确认/取消/重试动作，查看和推进训练任务 |
| `/agent/usage` | 用量与活动 | 查看 Token、模型调用、耗时、费用和低敏活动审计记录 |

所有管理页保留当前报告/Agent 会话的查询参数。用户从对话工作台切换到管理页时，可以继续处理当前上下文；直接打开管理页时，则显示全局管理数据或明确的空状态。

## 3. 共享交互设计

- 顶部保留 Agent 品牌、返回面试中心、模型设置和当前登录状态。
- 顶部增加四项页签导航，当前页签使用现有 primary 样式，未选中项使用现有 secondary/ghost 风格。
- 管理页使用统一页面标题、说明、刷新按钮和空状态，避免每个卡片重复解释上下文。
- 对话页保留报告选择、会话列表、工作流、Loop 轨迹和教练对话；动作、记忆、用量只显示轻量摘要和跳转入口。
- 所有“确认执行”仍然保留二次确认语义；页面拆分不改变原始面试报告和简历只读保护。

## 4. 分阶段实施

### 阶段一：路由与页面骨架

1. 将已经验收的 Agent 功能合入 `develop-agent`。
2. 从开发基线创建独立页面优化分支。
3. 增加 Agent 共享导航和四个稳定路由。
4. 将现有管理面板按职责显示到对应页面，先复用原组件和状态逻辑，降低回归风险。

### 阶段二：交互和视觉收敛

1. 对话工作台只保留对话闭环和当前运行上下文。
2. 管理页补充跨会话筛选、分页或折叠细节（以现有 API 能力为边界）。
3. 对加载、空数据、登录失效、请求失败和重试状态统一文案与布局。
4. 根据验收反馈调整导航命名和卡片密度。

### 阶段三：验证与候选部署

1. 增加路由切换、查询参数保留、管理操作和刷新恢复的前端测试。
2. 运行前端 lint、类型检查、构建和 Agent 相关 E2E/单测。
3. 只部署到候选环境 `18084` 做真实验收，不触碰 `18083`。
4. 用户验收通过后，再把页面优化分支合入 `develop-agent`。

## 5. 验收标准

- 从 `/agent` 可以进入四个 Agent 子页面，刷新或前进/后退后页面状态可恢复。
- 从面试详情页点击“AI 复盘”仍然进入 `/agent?sessionId=...`，不创建隐式空会话。
- Agent 对话、Loop 执行、消息恢复、动作确认/重试、记忆编辑删除、用量和活动读取行为不回归。
- `/agent` 不再同时展示完整的记忆、用量、活动和动作管理列表；这些内容分别在管理页可用。
- 不改变普通面试、RAG、简历和正式环境的运行方式。
