# Agent 候选环境验收清单

## 目的

验证 Agent 不只输出建议，还能在用户确认后完成一项可追踪的训练动作，同时保证原始面试、评分和简历不被覆盖。

## 环境

- 候选环境：`http://101.126.33.248:18084`
- 正式环境：`http://101.126.33.248:18083`，验收期间不得操作或重启
- 数据库仅用于故障排查，不作为页面功能验收的替代

### 候选环境路由约束

候选前端与正式前端运行在同一台宿主机时，不能直接复用正式环境的 Nginx
配置。候选前端容器内的所有 `/api/`、`/ws/` 和 Agent SSE 请求必须转发到候选网络中的
`candidate-app:8080`；正式前端才转发到 `app:8080`。两套环境的页面可以都返回 HTTP 200，
但如果目标服务写错，业务响应会来自另一套数据库，表现为登录状态、活动记录、长期记忆和
会话列表互相不一致。

部署后至少检查：

```powershell
docker exec interview-guide-agent-candidate-frontend nginx -t
docker exec interview-guide-agent-candidate-frontend nginx -T | Select-String 'proxy_pass'
```

候选配置应只出现 `candidate-app:8080`，并在登录后通过页面或接口确认 Agent 活动记录、
长期记忆、训练任务和会话列表均来自候选环境。`18083` 不应停止、重启或替换。

## 主流程验收

### 自动化动作验收

在候选环境可以先执行以下脚本，验证受控动作接口的核心状态机；脚本使用临时账号，
不调用 Agent 模型，不产生额外模型费用：

```powershell
pwsh -NoProfile -File .\scripts\agent-action-acceptance.ps1 `
  -BaseUrl http://101.126.33.248:18084
```

脚本覆盖草稿生成、幂等、人工编辑、确认前不落任务、确认后创建任务、任务状态推进、
结束状态保护和跨账号拒绝。通过后再进行下面的页面验收。

### 1. 生成并确认训练任务

1. 登录候选环境，打开一份已完成的文字面试报告。
2. 进入「AI 面试教练」，运行一次「复盘本场面试」。
3. 在对话输入区的「快捷动作」点击「创建训练任务」。
4. 确认页面出现「创建训练任务」动作草稿，状态为「待确认」。
5. 编辑草稿内容后保存修改，再点击「确认创建任务」。
6. 验证训练任务出现在「训练任务」区域，初始状态为「待开始」。

预期：动作没有确认前不创建任务；确认后只新增独立训练任务，不修改报告内容。

### 2. 从训练任务开始专项面试

1. 在待开始任务上点击「开始专项面试」。
2. 验证任务状态变为「进行中」。
3. 验证进入新的文字面试创建流程，而不是打开原面试。
4. 验证新面试的问题围绕训练任务中的重点生成。
5. 返回 Agent 页面，确认原面试的问题、回答、评分和报告仍保持不变。

预期：新面试请求只携带已确认的 Agent 动作标识；未确认、已取消或其他用户的动作不能作为训练重点。

### 3. 失败、重试和恢复

- 模拟动作执行失败，验证动作显示「失败」并提供「重试动作」。
- 重试成功后验证状态变为「已保存」，重复点击不会创建重复任务。
- 在 Agent 运行期间刷新页面，验证会话和运行状态可以恢复。
- 在候选 API 重启后刷新页面，验证已持久化的 Agent 消息不会重复。

### 4. 会话和权限隔离

- 同一份面试报告创建两个 Agent 会话，验证消息和动作列表互不串线。
- 使用另一账号访问动作或训练任务，验证服务端返回无权访问。
- 离开 Agent 页面再返回，验证当前面试报告和 Agent 线程仍能恢复。

### 5. 记忆管理和用量定位

1. 从 Agent 对话工作台进入「记忆管理」，确认 URL 仍保留当前 `sessionId` 和
   `agentSessionId`。
2. 确认「本场面试会怎么使用记忆」区域显示当前面试方向、实际生效的记忆数量和
   不会覆盖原始报告/简历的说明；适用方向不一致的记忆应明确显示为本场不会注入。
3. 编辑一条记忆并刷新页面，确认内容、适用方向和有效期保持；删除后确认它不再出现在
   可管理列表中。记忆管理操作不得修改面试报告、回答、评分或简历文件。
4. 至少完成一次 Agent 运行后进入「用量与活动」，确认「按运行明细」每行能同时显示
   面试名称、Agent 会话名称、运行状态、输入/输出/总 Token、模型调用次数、耗时和费用
   （未配置计价时显示「未计价」）。
5. 点击运行明细的「打开这场 Agent 对话」，确认回到同一份面试和同一个 Agent 会话；
   在「活动轨迹」中确认事件也显示来源面试和 Agent 会话，无法关联的历史事件显示为
   未关联，而不是伪造名称。
6. 刷新管理页或复制带查询参数的 URL，确认页面仍能恢复当前来源；未登录时管理接口
   应返回登录失效提示，不应展示其他账号的统计或活动。

预期：记忆页能回答“哪些记忆会影响下一次运行”，用量页能回答“哪场面试、哪个 Agent
会话消耗了多少”，而不是只展示无法定位的动作名称。

### 6. 候选与正式环境隔离

- 候选 `18084` 页面应加载本次页面优化构建，并能访问候选 API；正式 `18083` 保持原有
  页面资源和服务状态。
- 候选环境检查不得停止、重启或替换正式环境容器；完成验收后保留候选备份，便于回滚。

## 验收结论

只有以下条件同时满足，才允许将功能分支合入开发总分支：

- 主流程 1、2 全部通过；
- 原始面试资料未被修改；
- 失败重试、刷新恢复和账号隔离通过；
- 记忆应用预览、记忆编辑删除、运行明细来源定位和活动来源跳转通过；
- 候选与正式环境隔离检查通过；
- 前端 Agent E2E、后端相关测试和生产构建均通过；
- 候选环境验证通过后，由用户确认验收。
