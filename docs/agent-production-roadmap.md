# Agent 后续生产化方案

## 目标

在不改变普通面试、语音面试、RAG 会话和现有 Agent 使用方式的前提下，把 Agent 从“可用”推进到“可观测、可评测、可演进”。每个阶段独立开发、独立验收，先补数据和质量基线，再扩大 Agent 自主能力。

## 当前基线

已具备：

- Skill、RAG、面试报告和短期上下文编排；
- 有边界的 Agent Loop 和只读工具；
- 多 Agent 会话、正式登录、账号隔离；
- SSE 流式输出、重试、备用 Provider、取消和重启恢复；
- 轻量结构化长期记忆；
- 后端、浏览器和远程真实环境验收脚本。

## 分阶段实施

### 阶段一：观测与质量基线（当前开发）

1. 采集模型响应中的 prompt/completion/total token；Provider、实际模型、模型调用耗时和终态统一进入 Micrometer 指标。
2. 费用按 Provider/模型配置单价计算；未配置单价时只记录 Token，不伪造费用。
3. 保持低基数标签，不记录用户问题、完整回答、会话 ID 或 API Key。
4. 增加 Agent 真实样本评测入口，至少覆盖：回答完整性、面试事实一致性、RAG 来源使用、Markdown 可读性、Loop 是否越界。
5. 将质量样本、模型版本、Prompt 版本、代码版本和费用信息绑定，形成可比较的回归报告。
6. 将最近一次运行的聚合 Token、模型调用次数、模型耗时和已配置费用持久化到 Agent 会话，供页面刷新后查看；同时按 `runId` 保存每次终态运行记录，支持当前账号跨面试、跨对话累计查看。

验收：指标能在 `/actuator/prometheus` 查询；一次成功、重试、备用 Provider 和失败请求都有可区分的调用/耗时统计；缺少 Provider usage 时请求仍正常完成；正式 Agent 验收脚本能读取 `runUsage` 摘要和长期记忆摘要。

当前实现先支持 `app.ai.agent.cost.providers.<provider>` 的配置文件单价，字段为
`input-per-million`、`output-per-million` 和 `currency`。模型管理页现在也支持按 Provider
保存数据库价格覆盖；数据库覆盖优先，清除覆盖后自动回退到配置文件单价。费用仍按每百万
Token 计算，未配置时只记录 Token，不猜测费用。

当前已增加离线质量门禁：`AgentQualityEvaluator` 对完整性、事实禁用项、RAG 引用边界、
Markdown 换行/代码围栏和 Loop 步骤预算做可重复检查；`agent-eval/dataset-v1.jsonl`
提供 dev/holdout 样本契约，执行入口为 `./gradlew :app:agentEvaluation`。它只证明
可观测的回归条件，真实模型回答的语义正确性仍需后续真实样本评测和人工抽检。

真实样本采集已自动化：`scripts/agent-quality-collector.ps1` 会在正式登录环境逐条执行评测语料，
从持久化会话提取回答、来源、Loop 观察和用量，生成 `agentEvaluation` 可消费的 JSONL；SSE
业务错误、未进入 `RUNNING` 或非 `COMPLETED` 状态会直接失败，不会把空回答写入质量样本。

当前集成分支已增加运行用量摘要和账号累计用量：用量只保存聚合值，不保存 Prompt、完整回答或
密钥；最近一次用量仍保存在 Agent 会话中，历史记录按 `runId` 幂等保存到独立表，账号累计
汇总在数据库侧聚合，不按历史记录总量加载到应用内存。重试和备用 Provider 的模型调用会合并计数。
没有配置单价时页面明确显示“未配置单价”。旧会话迁移时只可
恢复会话表中保留的最近一次用量，迁移完成后的每次运行都会完整计入累计记录。

### 阶段二：Agent Loop 增强

- 每个步骤独立超时、重试和结果校验；（已完成基础实现）
- Loop 计划在启动、每个步骤边界和失败点保存下一个待执行索引；恢复时复用原计划，
  不重复已经完成的观察；并持久化并行组已完成步骤集合，应用重启后也不重复成功兄弟步骤；（已完成，并通过远程重启恢复验收）
- 阶段进度、来源、Loop 检查点和模型用量按 `runId` 校验，旧任务的迟到回调会被忽略；
  （已完成）
- 每一步结构化记录动作、观察、状态、尝试次数、耗时和失败原因，并发布低基数 Loop
  步骤计数与耗时指标；（已完成）
- 依赖明确的步骤允许并行执行；（已完成保守实现，仅对相邻 `[parallel]` 只读步骤并发）
- 统一 Loop 总预算、工具调用预算和模型调用预算；规划、重试、上下文压缩重试、备用
  Provider 和只读工具共用同一个 Agent 运行边界；达到上限后停止继续消耗资源；（已完成）
- 失败时支持从最近一个已完成观察点继续，而不是整轮无限重跑。（已完成基础实现）

不允许模型直接自主写入业务数据；已经通过统一的 Agent 动作状态机开放少量受控动作。
训练任务、长期记忆、面试名称、复习日程、报告导出和简历编辑版都必须经过 owner 校验、
幂等键、预览/确认、审计和失败重试。未接入状态机的高风险写入仍保持关闭。

### 阶段三：记忆与用户体验

- 查看、编辑、删除单条长期记忆；（已完成基础能力）
- 展示记忆来源、生成时间、置信度和适用岗位；（已完成基础字段和前端展示）
- 生成 Agent 上下文时按当前面试方向过滤不适用记忆；（已完成基础隔离）
- 支持记忆过期和按岗位隔离；（已完成基础策略，默认 180 天过期，可配置开关和保留天数）
- 运行中的 Agent 在多标签页、刷新和断线后保持一致状态；（已完成基础恢复，页面重新聚焦或网络恢复时会主动同步持久化状态）
- 对 Agent 运行、只读工具调用和长期记忆变更记录低敏审计事件；（已完成基础记录和当前用户只读查询，不保存工具参数或返回内容）
- 对 Agent 对话线程的新建、重命名和归档记录低敏生命周期审计；（已完成，事件只保存稳定会话标识）
- 简历优化动作先保存为独立编辑版草稿；确认动作不会覆盖原始上传文件，用户可在简历管理页继续手动编辑、应用到后续面试或导出；（已完成首版）

### 阶段四：平台能力

- 知识库、文档和向量数据增加个人 owner 隔离；（已完成基础版本：新登录用户的知识库/RAG 会话按 owner 隔离，历史 NULL owner 数据继续共享兼容）
- 增加邮箱验证、密码找回；（已完成基础能力，默认关闭，需 SMTP 配置后开启）
- 增加管理员治理和安全审计；（已完成基础账号治理：状态/角色、最后管理员保护、会话失效和低敏安全审计；完整业务审计仍未完成）
- 有明确外部系统需求时再接入 MCP；
- 在治理完成后再考虑把训练计划草稿应用为批量任务、修改原始报告或覆盖原始简历等高风险动作；
  当前只允许保存独立草稿或通过受控动作创建独立任务，不改变原始面试资料。

## 当前分支交付边界

当前集成验收分支完成阶段一的“Token/Provider/模型性能观测”、运行用量摘要、账号累计用量、可选单价
费用指标、价格管理页和真实样本报告入口；阶段二的有边界 Loop、明确标记的只读步骤并行执行、
逐步骤检查点、步骤可观测性和远程重启恢复也已完成验收；阶段三已增加轻量长期记忆项管理、
岗位过滤、默认 180 天过期策略和页面/断线状态恢复；阶段四已增加默认关闭的邮箱验证、
密码找回和重置后会话失效能力。
管理员治理分支增加了账号角色、停用/启用、最后管理员保护、管理员会话权限和低敏安全审计；管理员页面现在也能查询 Agent 运行、记忆变更和只读工具调用的低敏审计记录；
管理员首批账号通过 `APP_AUTH_ADMIN_EMAILS` 配置，未配置时不会改变普通用户行为。

Loop 并行仍是保守开启：只有相邻步骤都带 `[parallel]` 标记且在并行额度内才会并发，未标记
步骤保持串行；并行组出现失败时恢复点回到最早失败步骤，避免跳过未完成工作。
恢复时会根据已持久化的完成步骤集合跳过并行组中已经成功的兄弟步骤；集合仅保存非负、去重后的有限索引，
检查点索引或步骤集合越界时过滤并回退，避免把损坏或不完整的恢复状态误判为已完成。

## 本轮可靠性修复

- 远程候选环境使用独立数据库完成两轮正式 Agent 验收和一次应用重启恢复验收；原有
  `18083` 服务未停止、未替换。
- 发现并修复恢复竞态：旧实例迟到的阶段、来源、Loop 和用量事件不能覆盖新实例的运行。
- Loop 计划会在执行前保存；每个步骤完成或失败后立即保存检查点，恢复任务从最近检查点
  继续。检查点写入失败不会阻断正常回答，但会记录日志并由恢复状态兜底。
